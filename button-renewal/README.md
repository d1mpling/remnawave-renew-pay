# remnawave-renew

Кнопка «Продлить» на странице подписки Remnawave: выбор тарифа и периода, оплата через **YooKassa** или **Platega**, автоматическое продление пользователя в панели.

## Как это работает

1. Установщик кладёт рядом с панелью маленький сервис `renew-pay` (Node.js, без зависимостей).
2. В nginx страницы подписки добавляется `sub_filter`, который подгружает `renew-button.js` с сервиса оплаты.
3. Кнопка показывает тарифы (`plans.json`), человек выбирает период и уходит на оплату.
4. После оплаты провайдер шлёт уведомление, сервис продлевает `expireAt` и выставляет сквады тарифа. Раз в минуту сервис сам проверяет платежи, так что потерянное уведомление не страшно.

## Что нужно заранее

- Сервер с работающими Remnawave и страницей подписки (`remnawave-nginx`, `remnawave-subscription-page`), доступ по SSH под root.
- API-токен Remnawave: Настройки → API-токены → создать.
- Ключи провайдера: YooKassa (shopId и секретный ключ) или Platega (MerchantId и секрет).

### Где будет жить сервис оплаты

- **На домене подписки по пути `/renew-pay` (рекомендуется).** Адрес вида `https://sub.example.com/renew-pay`. Используется уже выпущенный сертификат страницы подписки, новый DNS, порт и сертификат не нужны. Подходит, когда для панели и подписки выпущены отдельные сертификаты.
- **На отдельном домене**, например `https://pay.example.com:8443`. Нужны A-запись, открытый порт (`ufw allow 8443/tcp`) и сертификат именно на этот домен. Если у вас отдельные сертификаты на каждый домен, выпустите ещё один и укажите его пути при установке (пути так, как их видит контейнер nginx, то есть он должен быть примонтирован).

## Установка

1. Создайте репозиторий на GitHub, залейте `install.sh`, `app/server.js`, `app/renew-button.js`, `README.md`.
2. В `install.sh` замените `YOUR_USER/remnawave-renew` в строке `REPO_RAW` на свой репозиторий.
3. На сервере под root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YOUR_USER/remnawave-renew/main/install.sh)
```

Появится меню:

```
Выберите режим:
  1) Всё на домене подписки      (sub.ваш-домен/renew-pay, без нового DNS и порта)
  2) Отдельный домен для оплаты  (pay.ваш-домен:8443, нужен свой сертификат)
  3) Обновить код
  4) Удалить
```

После выбора режима установщик спросит, какую платёжку использовать (YooKassa или Platega), затем ключи, сеть и токен Remnawave, домен страницы подписки и сквады для тарифов. Меню можно пропустить: `install.sh path`, `install.sh domain`, `install.sh update`, `install.sh uninstall`. Потом он сам:

- скачает и проверит файлы, создаст `/opt/renew-pay` (`.env` с правами 600, `docker-compose.yml`, `data/plans.json`);
- запустит контейнер `renew-pay`;
- добавит в nginx `sub_filter` и `location /renew-pay/` в блок подписки (или отдельный server-блок для домена оплаты), проверит `nginx -t` и перезагрузит. Перед правкой делается бэкап `nginx.conf.bak.<дата>`, при ошибке конфиг откатывается сам;
- проверит `https://pay.../health` снаружи.

Правки nginx помечены маркерами `# renew-button begin/end`, `# renew-pay-loc begin/end` и `# renew-pay begin/end`, поэтому повторный запуск ничего не дублирует, а удаление их вычищает.

## Настройка уведомлений (обязательно)

Адрес зависит от места размещения (установщик выведет готовый в конце). Для режима по пути:

- **YooKassa**: Интеграция → HTTP-уведомления. URL `https://sub.example.com/renew-pay/yookassa/webhook`, событие `payment.succeeded`.
- **Platega**: настройки магазина → Callback URL `https://sub.example.com/renew-pay/platega/callback`.

Для отдельного домена: `https://pay.example.com:8443/yookassa/webhook` и `.../platega/callback`.

## Проверка

1. Откройте страницу подписки в режиме инкогнито, нажмите «Продлить».
2. Выберите самый дешёвый тариф и оплатите.
3. Смотрите `docker logs -f renew-pay`. Должна появиться строка вида `payment ...: имя vpn +1 мес. до 2026-...`.
4. Проверьте в панели срок и сквады пользователя.

## Тарифы и цены

Файл `/opt/renew-pay/data/plans.json`:

```json
{
  "vpn": {
    "name": "Обычный VPN",
    "desc": "Без белых списков.",
    "squads": ["uuid-сквада"],
    "prices": { "1": 149, "3": 399, "6": 749, "12": 1299 }
  }
}
```

Можно добавлять любые тарифы и периоды. После правки: `cd /opt/renew-pay && docker compose restart`. Цены берутся только с сервера: клиент присылает лишь тариф и период. Пустой `squads` значит «сквады не менять».

## Управление

```bash
bash <(curl -fsSL .../install.sh) update      # обновить код
bash <(curl -fsSL .../install.sh) uninstall   # удалить
docker logs -f renew-pay                      # логи
```

## Поведение при продлении

- Срок считается от текущей даты окончания, если подписка ещё активна, иначе от сегодняшнего дня.
- Пользователи с датой окончания дальше 2090 года («бессрочные») срок не меняют, но сквады тарифа получают.
- Сквады пользователя **заменяются** на сквады купленного тарифа.
- Один платёж применяется один раз (id в `data/processed.json`).

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Кнопки нет | `curl -s https://sub.example.com/<shortUuid> \| grep -c renew-button` должно быть 1. Ctrl+F5 или инкогнито. Если 0, смотрите блок `# renew-button` в nginx.conf |
| Кнопка в углу, а не в шапке | Скрипт не нашёл ссылку Telegram в шапке, положение можно поправить в функции `place()` |
| `.../renew-pay/health` недоступен | `docker exec remnawave-nginx nginx -t`, блок `# renew-pay-loc` в nginx.conf; для отдельного домена ещё DNS, порт в файрволе и сертификат |
| Оплатили, но срок не изменился | Лог `docker logs renew-pay`; уведомление не настроено в кабинете провайдера; для YooKassa продление всё равно случится в течение минуты по автопроверке |
| В логе `PATCH /api/users -> 400` | Ответ панели в строке лога; пришлите её целиком |
| Сертификат не подходит для домена оплаты | Используйте домен, покрытый сертификатом, или выпустите сертификат на него |
